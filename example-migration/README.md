# Gemini Eval Framework — Minimal Model Migration Example (Antigravity & Vertex AI)

This folder contains a minimal, end-to-end runnable Python example showing how the files in `/Applications/antigravity/gemini-eval/` work together for a **Gemini Model Migration** (`gemini-2.5-flash` → `gemini-3.8-flash` / `gemini-4-pro`) on **Google Cloud Vertex AI**.

---

## 1. How the Files in `gemini-eval/` Fit Together

| File in `gemini-eval/` | Role in the Methodology |
|---|---|
| `build-eval.md` | **Phase 1 Guide**: Defines how to scope one flow, build/approve the input dataset, choose a grader (including the Gemini Judge menu: `gemini-3.8-flash`, `gemini-3.5-pro`, `gemini-4-pro`), and wire up the runner (`results.jsonl` + `traces/`). |
| `eval-audit.md` | **Health Checklist**: Verifies task design, harness hygiene (separating API errors in `errors.jsonl` from model failures in `results.jsonl`), and statistical noise floor. |
| `eval-hillclimb.md` | **Phase 2 Guide**: Defines the iterative hill-climbing loop (`baseline` → `v1` → `v2`) using a `train`/`test` split, `run_command` background execution, and `invoke_subagent` for per-round train-trace analysis. |
| `cost-hillclimb.md` | **Cost Optimization Guide**: Specializes hill-climbing when the goal is reducing cost via the `model × thinking/effort` staircase walk (`gemini-4-pro` → `gemini-3.8-flash` → `gemini-3.8-flash-lite`) while holding quality constant. |
| `report/runner-scaffold.py` | **Runner Template (Python 3)**: Production-grade Python script with `--variant`, `--model`, `--reps`, `--approve-harness` integrity hashing, crash-safe resume, and `traces/` writing. |
| `report/build-report-lite.py` | **Report Builder (Python 3)**: Reads a flow directory (`flow/baseline`, `flow/v1`, ...) and generates `flow/report.html` and `flow/trajectory/scores.tsv`. |
| `report/SCHEMA.md` | **Data Contract**: Exact specification for `_state.json`, `results.jsonl`, and `traces/<id>_rep<k>.json`. |

---

## 2. Files in This Minimal Example (`example-migration/`)

- `cases.json` — **6 synthetic support tickets** (3 `train`, 3 `test`) testing JSON triage classification, subtle outages, and emotional urgency traps.
- `prompts.json` — System instructions for `baseline`, `v1` (model swap only to `gemini-3.8-flash` / `gemini-4-pro`), and `v2` (model swap + prompt tuned for strict raw JSON formatting and escalation boundary rules).
- `run-eval.py` — Copy of `../report/runner-scaffold.py` with `load_cases()`, `run_case()`, and `grade_case()` implemented in Python for **Vertex AI Gemini (`generateContent`)**.
- `flow/_state.json` — Declares `train_ids`, `test_ids`, `metrics`, `perf_fields`, and the approved `harness_sha`.
- `flow/report.html` — Static HTML comparison report generated by `../report/build-report-lite.py`.

## 3. Step-by-Step Instructions to Run

### Option A: Live Run Against Vertex AI Gemini (`gemini-2.5-flash` → `gemini-3.8-flash` / `gemini-4-pro`)

1. **Authenticate with Google Cloud & set your Project ID and Region:**
   ```bash
   cd /Applications/antigravity/gemini-eval/example-migration
   gcloud auth login
   export VERTEX_PROJECT_ID="your-gcp-project-id"
   export VERTEX_REGION="us-central1"   # or "global"
   ```

2. **Clear any previous simulated run (optional, since the runner is resume-aware and skips completed `(case, rep)` rows):**
   ```bash
   rm -rf flow/baseline flow/v1 flow/v2 flow/trajectory flow/report.html
   ```

3. **Step 1 — Run `baseline` on the older model (`gemini-2.5-flash`):**
   *(Note: Pass `--approve-harness` on the first run to record the SHA-256 of `run-eval.py` and `cases.json` into `flow/_state.json`)*
   ```bash
   python3 run-eval.py --flow flow --variant baseline --model gemini-2.5-flash --approve-harness
   ```

4. **Step 2 — Run `v1` on the newer model (`gemini-3.8-flash` or `gemini-4-pro`) with the unchanged prompt:**
   ```bash
   python3 run-eval.py --flow flow --variant v1 --model gemini-3.8-flash
   printf "# Migrate model from gemini-2.5-flash to gemini-3.8-flash (unchanged prompt)\n" > flow/v1/change.md
   ```

5. **Step 3 — Run `v2` on the newer model (`gemini-3.8-flash` or `gemini-4-pro`) with the tuned prompt:**
   ```bash
   python3 run-eval.py --flow flow --variant v2 --model gemini-3.8-flash
   printf "# Add explicit raw-JSON (no markdown fences) and escalation boundary rules for Gemini 3.8 Flash\n" > flow/v2/change.md
   ```

6. **Step 4 — Build the HTML Report and TSV Trajectory:**
   ```bash
   python3 ../report/build-report-lite.py flow
   open flow/report.html
   ```
